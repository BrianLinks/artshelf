# ArtShelf

A creative-services marketplace: clients browse artists by category, hire them under explicit usage licenses, and pay through a local escrow-style ledger. Everything runs offline with no paid APIs.

**Version 1.0.** A complete offline marketplace: accounts and roles, artist profiles with moderator approval, validated uploads with thumbnails and color palettes, a license engine and listings, simulated payments with escrow on an append-only double-entry ledger, a Request Board for custom commissions, verified reviews, a support desk and help center, copyright takedown notices, an in-app notification outbox, local text and color search, and a React web app. See [CHANGELOG.md](CHANGELOG.md), [ARCHITECTURE.md](ARCHITECTURE.md) and [docs/API.md](docs/API.md).

## Requirements

- Node.js 20 or newer
- A C/C++ toolchain is only needed if `better-sqlite3` has no prebuilt binary for your platform

## Getting started

```bash
git clone <your-repo-url> artshelf
cd artshelf
npm install
cp .env.example .env     # optional: the defaults work as-is
npm run migrate          # creates ./data/artshelf.db
npm run seed             # optional: demo accounts, generated artwork, sales and a request
npm run dev              # API on http://localhost:3000
npm run web:dev          # in a second terminal: the UI on http://localhost:5173
```

`npm run seed` prints the demo accounts (artists, clients, a moderator and an admin, all sharing one password). It never runs when `NODE_ENV=production`. All demo artwork is generated by the program, so there are no third-party images. To create a real administrator instead:

```bash
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='a long passphrase' npm run create-admin
```

`.env` is not loaded automatically. Export the variables in your shell, or use `node --env-file=.env` for the built server.

## Web app

**Quickest way to run everything:** `npm run app` builds the UI and starts the server, then open http://localhost:3000. Use one terminal, in the project folder. Stop it with Ctrl+C and rerun after changing UI code.

The UI lives in `web/` (React, TypeScript, Vite). It talks to the API over `/api` and uses hash routes such as `#/search?q=cat`.

```bash
npm run dev        # API on http://localhost:3000
npm run web:dev    # UI on http://localhost:5173, proxying /api to the API
```

For a single server, run `npm run web:build`, then `npm start`: when `web/dist/index.html` exists the API serves the app (with a content security policy) and falls back to it for non-API paths.

| `POST /api/requests` | client, artist | Post a request (`title`, `description`, `category`, `budgetCents`) |
| `GET /api/requests/:id` | public while open or proposed; then parties and staff | Request detail |
| `GET /api/requests/mine`, `/assigned` | signed in / artist | Requests you posted / jobs you were hired for |

| `POST /api/requests/:id/revise`, `/approve`, `/cancel` | client | Ask for changes, approve (pays the artist), or cancel before accepting |
| `POST /api/requests/:id/dispute` | client or artist | Freeze a funded request |
| `GET /api/requests/:id/delivery`, `/events` | parties (staff while disputed / always for events) | Latest delivered file and the change history |
| `POST /api/moderation/requests/:id/resolve` | moderator, admin | Settle a dispute: `release` or `refund` |

| `GET /api/reviews?artist=` or `?listing=` | public | Reviews plus the artist's rating summary |
| `GET /api/reviews/artist/:id/rating`, `GET /api/reviews/:id` | public | Rating summary; one review (reviewer and staff also see moderation state) |
| `POST /api/reviews` | buyer or client | Review a completed order (`orderId`) or commission (`requestId`), once |
| `PUT /api/reviews/:id`, `POST /api/reviews/:id/flag` | reviewer / anyone else | Edit your review; report one as `spam`, `abusive`, `off_topic` or `other` |
| `GET /api/reviews/reviewable` | signed in | Completed purchases and commissions you have not reviewed |
| `GET /api/moderation/reviews`, `POST .../reviews/:id/hide`, `/dismiss`, `/restore` | moderator, admin | Review reports queue and decisions |
| `GET /api/support/help`, `/help/:slug` | public | Help center articles, searchable with `?q=` |
| `POST /api/support/tickets`, `GET /api/support/tickets`, `GET .../:id`, `POST .../:id/messages`, `/close` | signed in | Open and follow your support tickets |
| `GET /api/support/queue`, `POST .../tickets/:id/assign`, `/resolve` | moderator, admin | Staff queue; staff may add internal notes with `internal: true` |
| `POST /api/takedowns` | signed in | File a copyright notice against a listing (sworn statements and a signature) |
| `GET /api/takedowns/mine`, `/against-me`, `/:id` | claimant, artist, staff | Notices you filed, notices against you, one notice |
| `POST /api/takedowns/:id/counter` | listing's artist | Counter-notice after an upheld removal |
| `GET /api/moderation/takedowns`, `POST .../takedowns/:id/uphold`, `/reject`, `/reinstate`, `/close` | moderator, admin | Decide notices and counter-notices |
| `GET /api/notifications`, `POST .../:id/read`, `POST .../read-all` | signed in | Your in-app messages (`?unread=true`) |

| `GET /api/search` | public | Search published listings. `q` (words, prefix match, accents ignored), `color` (hex such as `dc1414`; encode `#` as `%23`) or `similarTo` (a listing id), plus the browse filters. `sort` = `relevance` (default), `newest`, `price_asc`, `price_desc` |

Search is fully local: SQLite FTS5 ranks text matches (title and tags count most), and each uploaded image gets a deterministic five-color palette. A color search ranks listings by perceptual (CIELAB) distance between palettes; `similarTo` uses another listing's palette. Run `npm run reindex` to rebuild the text index and compute palettes for older uploads.

Commissions follow the same simulated money rules as sales. Money is simulated: deposits come from an internal external account and no payment provider is involved. A paid order sits in escrow for `ESCROW_HOLD_DAYS` (default 7), then is released automatically unless the buyer opened a dispute. Commission is 15% for standard artists and 10% for premium artists, snapshotted on each order.

Original uploaded files stay private to their owner, moderators and admins. The public sees only listing metadata and the WebP preview.

Prices are integer cents everywhere. A listing has one base price; each license price is the base times a platform multiplier (Non-Commercial 1x, Commercial 2.5x, Broadcast 5x), rounded half up.

Errors are JSON: `{ "error": { "code": "...", "message": "...", "details": [...] } }`.

## Configuration

See [.env.example](.env.example). Invalid values stop the process at startup. In production `BCRYPT_ROUNDS` must be at least 10.

## Using the web app

Everything is reachable from the header: **Browse** (search by words, color or "more like this"), **Requests** (the board, with a form to post one), **Dashboard** for artists (profile, uploads, listings, earnings), **Support** and **Help**. Artists need a moderator to approve their profile before listings and bids go public: sign in as the demo moderator, or call `POST /api/moderation/artists/:userId/approve`. Moderation tools beyond the support queue are API-only; see [docs/API.md](docs/API.md).
